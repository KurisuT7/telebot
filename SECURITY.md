# Security policy

Do not report credentials, private messages, session data or exploitable details in a public issue.
Use GitHub's [private vulnerability reporting](https://github.com/KurisuT7/telebot/security/advisories/new)
for security reports. If that form is unavailable, open a public issue containing no vulnerability
details and ask the maintainer to enable a private reporting path.

Include the affected commit or release, impact, reproduction conditions and a minimal synthetic
example. Remove API keys, Telegram identifiers, messages, databases, session files, hostnames and IP
addresses before attaching logs or configuration.

Only the latest code on the default branch is maintained until the project publishes an explicit
version-support policy. Security reports are assessed individually; no response or release timeline
is guaranteed.
